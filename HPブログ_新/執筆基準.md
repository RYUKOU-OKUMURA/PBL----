# 新ブログ 執筆基準

- 作成日: 2026-11-06
- 状態: 確定（2026-11-06 本人了承）。
- 対象: `HPブログ_新/` の記事だけ。旧記事の修正には使わない。
- テーマと順番は [テーマ台帳](テーマ台帳.md) を正本にする。

## 1. 旧基準から変えること

| 項目 | 旧基準 | 新基準 |
|---|---|---|
| 目的 | 検索語で流入を取る | 診療案内に来た人の疑問に答え、予約を決めやすくする |
| 構成 | PASONAの5見出し | 読者の問いに答える見出しを3〜5個 |
| 長さ | 本文2,500〜3,800字 | 約2,000字を目安。問いに答え切れる長さを優先する |
| 中心の材料 | 論文とエビデンス | 院長の見立てと判断。論文は必要なときだけ |
| 書き出し | 悩みをあおって引き込む | 最初に問いへ答える |
| 研究の数字 | 要約に必須 | 必須にしない |

使わなくなるもの: `seitai-blog-pasona` スキル、`japanese-blog-style-guard` の合否。

引き続き使うもの: マスターガイドの「匿名エピソードの安全ルール」「6. 安全・コンプライアンス」「11. 固定要素」「12. 強調表現」、`medical-compliance-checker`、`chinese-char-detector`。

## 2. 書く前に決めること

台帳に次の4つが書けないテーマは、書き始めない。

1. 答える問い（読者の言葉で1文）
2. 行き先の診療案内
3. 院長の素材（音声メモ、施術中の説明、判断の基準のどれか）
4. 重なる旧記事

## 3. 本文の型

1. 問いへの答えを、最初の2〜3文で書く。
2. 見出しは読者の問いの形にする。
3. 院長の見立てを1か所以上入れる。「僕はこう見ている」「なぜそう判断するか」を書く。
4. 症状の記事には、先に医療機関へ行くべき場合を書く。
5. 本文の途中と末尾で、行き先の診療案内へリンクする。

誰が書いても同じ内容になる一般論は、長く書かない。診療案内と同じ説明を繰り返さず、リンクで渡す。

## 4. 文体

- 一人称は「僕」、院を指すときは「当院」。です・ます調。
- 体の説明は比喩を使わず、平易に直接書く。
- 題名、冒頭、見出しは、読者が普段使っている言葉、頭の中で言っている言い方で書く。例: 「ずっと座っていると腰が痛い」「揉んでもらっても、また痛くなる」。自分のこととして受け取ってもらうため。「腰だけ見ても足りない」「硬さの出どころ」のような書き手の言い回しを使わない。
- 不安をあおらない。「放置するとヤバい」「手遅れ」のような言い方はしない。
- 「事務職の方が多く来られます」のような来院者像だけの文は書かない。職業や生活場面は、原因の説明の中に入れる。
- 読者は一般の患者さん。社内の言葉や制作の話を本文に出さない。

## 5. 院長の言葉の入れ方

素材は、まずRedcord Vaultの施術記録（`10_文字起こし/02_整形済み/`）を見る。`PBL情報発信/施術記録` はここへのリンク。足りないテーマだけ、院長が5分ほど話す（音声メモでよい）。

1. テーマに関係する院長の説明を、施術記録から抜き出す（Vaultの `redcord-transcript-context-pack` を使える）。
2. 抜き出した説明や院長の話から下書きを作る。
3. 院長が読んで、自分の考えと違うところを直す。

公開する記事に使えるもの:

- 院長の見立て、説明の順番、体の説明のうち、誰にでも当てはまる形にできる部分

公開する記事に使わないもの:

- 患者さんの発言の引用
- 個別の経過、改善の話、施術後の変化
- 個人が推測できる内容。住んでいる地域など、本人が特定されるような具体的な話は絶対に使わない

注意すること:

- 施術記録には話者の区別がない。院長の発言と決めつけず、手順3で院長が確かめる。
- 音声認識の誤りが残っている。文字起こしの言い回しを、そのまま記事にしない。
- 録音データを記事の素材に使うことは、院長が了承している（2026-11-06）。公開記事に使えるのは、上の「公開する記事に使えるもの」だけ。
- 施術記録には全件、先頭に「残存リスクチェック」がある。全件ではなく、記事に使う箇所だけ院長が確認してから転記する。
- Vaultのプロットは考え方の参考にする。「毒」「9割」「老ける」のような強い言い方は使わない。
- 使った施術記録は、Vaultの文字起こし側に関連リンクを残す。記事側のリンクは、Vault内の管理メモに置く。
- 公開用の原稿には、患者ID、session_id、元のファイル名、ローカルのパス、残存リスクの欄を書かない。`post_to_wp.py` は本文からこれらを取り除かない。

## 6. 表現の上限

- 「治る」「再発しない」は禁止の言葉ではない。「再発しない治療を目指す」は当院の方針で、トップページの見出しにも使っている。院が目指すこと、施術の質へのこだわりとして使う。
- 書かないのは、読者の結果を保証する文だけ。例: 「通えば必ず治ります」「あなたの腰痛は再発しません」。語尾をやわらげて残さず、文ごと書かない。
- 頭痛は「悩む方も来られる」「診断は医療機関で」までにし、因果を言い切らない。
- 整骨院・病院・他院を悪く書かない。違いは事実で説明する。
- 記事に金額を書かない。料金は診療案内へリンクして渡す。

この上限は、読者の結果を保証する文を止めるためのもので、文章全体を弱めるためのものではない。

- 院長の見立てと考えは、自信を持って言い切る。言い切りと温度感が、この院に行ってみたいと思ってもらう材料になる。
- 硬い言い回しへの置き換えで、院長が話している感じを消さない。
- チェックで直すのは、重大と判定された文だけにする。軽い指摘は本文を直さず、院長に見せて判断してもらう。
- 院長が了承した本文は、先に院長へ見せずに書き換えない。

## 7. AI検索にも読まれるための最低限

Googleの公式見解では、AI検索のための追加要件や専用の書き方はない。次の内容は、普通に良い記事の条件として守る。

1. **結論を先に書く。** 問いへの答えを本文の最初に置く。
2. **院長にしか書けないことを入れる。** Googleは、経験に基づく独自の内容を勧めている。
3. **1文だけ抜き出されても誤解されない文にする。** AIは文を抜き出して要約する。読者の結果を保証する文に読めるものを作らない（これは当院の判断で、Googleの要件ではない）。
4. **表記をそろえる。** 次の通り。
   - 院長名: 奥村龍晃
   - 院名: フィジカルバランスラボ整体院
   - 施術: レッドコード整体
   - 症状: 脊柱側弯症
5. **大事な内容は文字で書く。** 画像の中の文字だけに頼らず、写真には内容の分かる説明を付ける。
6. **執筆者と日付を示す。** 固定要素の執筆者欄と、公開日・更新日を入れる。

やらないこと:

- `llms.txt` などAI専用のファイルを作る
- AIのために記事を細切れにする
- 順位やAIの回答を狙ってページを量産する
- 不自然な言及を集める

## 8. 固定要素と構造化データ

`post_to_wp.py` の事前検査が見る固定要素は、これまで通り入れる（TL;DR、執筆者、目次、免責、LINEボタン、フッター、JSON-LD）。

- **TL;DR:** 問いへの答えを80〜120字で書く。数字は必須にしない。
- **LINEボタン:** 新ブログ専用のリンク `https://lin.ee/9tbKaUW` を使う。
- **JSON-LD:** `Article` を基本にする。`FAQPage`・`HowTo` は本文に実際にあるときだけ入れる。
- **執筆者:** `author` を院の情報につなぐ。

```json
"author": {
  "@type": "Person",
  "name": "奥村龍晃",
  "jobTitle": "柔道整復師",
  "url": "https://physical-balance-lab.com/about/",
  "worksFor": {"@id": "https://physical-balance-lab.com/#clinic"}
}
```

## 9. 公開までの流れ

1. 台帳からテーマを選び、院長の素材を取る。
2. `投稿前/` に下書きを作る。
3. 院長が内容を確認する。
4. 固定要素を入れ、`medical-compliance-checker` と `chinese-char-detector` を通す。
5. 事前検査のあと、WordPressの下書きにする。タグは固定の17タグから関連するものを選ぶ。

```bash
python3 post_to_wp.py "HPブログ_新/投稿前/記事名.md" --preflight-only
python3 post_to_wp.py "HPブログ_新/投稿前/記事名.md" --draft --create-terms --no-featured
```

アイキャッチは本文に入れないので、`upload_image` で別にアップロードして `featured_media` を設定する。画像のアップロードはWAFの403で止まることがある。その画像は画質の値を変えて作り直す。

6. 予約投稿にするときは、ここで `01_ガイドライン・プロンプト/WordPress投稿・予約投稿運用.md` の3〜4（`fixed-elements`、`prepare`、`plan`）を済ませる。これらは保存された本文と日付を書き換えるので、確認より先に行う。`format` は使わない。文ごとに改行が入り、院長が確認した表示と変わるため。
7. WordPressに保存された本文を取り直し、固定要素を含む完成稿を、この基準と手順4の2つのチェックで確認する。

```bash
python3 format_wp_drafts.py export --status draft --ids POST_ID --out-dir QA_EXPORT_DIR
```

8. PCとスマホで表示を確認する。
9. 手順3で院長が本文を了承していれば、公開の了承を兼ねる（2026-11-07 本人）。公開日は [テーマ台帳](テーマ台帳.md) の運用ルールに従う。手順3のあとで本文を変えたときは、院長に見せ直す。
10. 予約投稿は、同じ文書の `approve` のあと、予約の適用と再検証（同文書の6〜7）へ進む。`japanese-blog-style-guard` の確認は、この基準での確認に置き換える。
11. 公開後、原稿を `投稿済み/` へ移し、台帳を更新する。診療案内へのリンク追加と、重なる旧記事の扱いを本人と決める。

手順7より後で本文や固定要素を変えたら、手順7からやり直す。

## 10. 公開前の確認

- [ ] 最初の2〜3文で問いに答えている
- [ ] 院長の見立てが入っている
- [ ] 行き先の診療案内へのリンクがある
- [ ] LINEボタンが新ブログ専用のリンクになっている（事前検査はリンク先を見ない。固定要素の見本は旧リンクのまま）
- [ ] 症状の記事に、医療機関へ行くべき場合が書いてある
- [ ] 読者の結果を保証する文がない
- [ ] 金額を書いていない
- [ ] 院長名・院名・施術名の表記がそろっている
- [ ] 患者ID、施術記録のファイル名、ローカルのパスが本文にない
- [ ] 患者さんが特定されるような地域などの話が本文にない
- [ ] 読者が読んで満足できる内容か、院長が確認した
