# PBLブログ記事執筆マスターガイド

このドキュメントは、PBL（フィジカルバランスラボ整体院）のブログ記事を、誰が書いても同じ品質で再現できるようにする統合ガイドです。

---

## 1. 文体・トーン

### 基本スタイル
- **一人称**: 「僕」
- **敬体**: です・ます調
- **トーン**: 専門性 × やさしさ × 励まし
- **語りかけ**: 「〜なんです」「〜ですよね」など自然な語りかけを適宜使用
- **ミニエピソード**: 匿名の短い相談例を各記事で1つ以上

### 読みやすさ（モバイルファースト）
- **段落**: 2-4文で改行
- **見出し**: `##` と `###` を使用
- **太字**: 重要語の最小限強調
- **記事長**: 目安3000文字

### ナラティブ比率
- 本文の **70%以上** はプレーンな段落で書く
- 箇条書きは主に「今日からできること」セクションのみ
- 箇条書きは可能なら番号付き、1セクション最大5項目

### 匿名エピソードの安全ルール
- 使ってよいのは「よくある相談例」または「個人が特定されないよう加工した来院時の悩み」まで
- 年齢・性別・職業・来院時期などを組み合わせて個人が推測できる情報はぼかす
- 改善結果、施術後の変化、ビフォーアフター、効果を示す体験談は原則入れない
- 結果や変化に触れる必要がある場合は、公開前に `medical-compliance-checker` で高リスク表現として確認する

### 専門用語の扱い
専門用語は正確に使用し、**直後に平易な説明・比喩を必ず補う**。

| 専門用語 | 平易な説明 |
|---------|----------|
| 神経筋制御 | 筋肉と神経のチームワーク |
| ウィークリンク | 動作の鎖の中の弱い環 |
| 免荷 | 体重の一部を預けて負担を軽くする工夫 |
| 不安定性 | 小さな揺れで微調整を引き出す刺激 |
| トリガーポイント | 筋肉の中の小さな結び目 |
| 筋膜癒着 | 洗濯物が絡まったようにくっつく |

### 検索キーワードと平易語の両立
- **読者が検索しそうな言い方を主軸にする**: `タイトル`、`H1`、`TL;DR`、`メタディスクリプション`、主要な`H2`では、患者さんがそのまま入力しそうな語を優先する  
  例: `大人の側弯症`、`背骨の並び方`
- **専門語は補助的に使う**: 精度や検索意図の補強に必要な専門語は、本文前半で1〜2回まで自然に使ってよい  
  例: `大人の側弯症（医学的には成人側弯症）`
- **初出で橋渡しする**: 専門語を出すときは、`専門語（平易語）` か `専門語、つまり平易語` の形で必ず橋渡しする
- **2回目以降は平易語を主役にする**: 初出以降は、読者が頭の中で処理しやすい言い方を基本とする
- **本文で研究者名は基本出さない**: 本文では `2025年の研究では`、`複数の研究をまとめたレビューでは` のように紹介し、研究者名（`Uchidaさんたち` `Smithら` 等）は参考文献に集約する
- **限界をセットで書く**: 研究結果を紹介したら、同じ段落で必ず限界を添える（`横断研究が中心で因果は断定できない`、`研究の確かさは高くない`、`人数が限られる` など）。限界のない結果紹介は未完成
- **言い過ぎない**: 本文の主張は研究が支持する範囲を超えない。`証明された` `必ず〜する` ではなく `〜の可能性が示された` `関連が報告された`
- **業界語をそのまま出しすぎない**: `介入`、`個別化`、`エビデンス強度`、`生活機能スコア` などは、患者向け本文では原則言い換える

| 固めの表現 | 推奨表現 |
|-----------|---------|
| 成人側弯症 | 大人の側弯症（医学的には成人側弯症） |
| アライメント | 背骨の並び方（アライメント） |
| 介入では | 調整を始めるときは / 対応としては |
| 個別化が重要 | その人に合わせて考えることが大切 |
| エビデンス強度にばらつきがある | 研究の確かさには差がある |
| Smithらの研究では | 2025年の研究では / 複数研究をまとめたレビューでは |

## 2. 記事構成パターン（PASONA）

### 標準フロー
1. **【Problem】問題提起** - 読者の悩みを代弁し、共感を明確化
2. **【Agitation】背景説明** - なぜ起こるのか、放置リスクを穏やかに明示
3. **【Solution】解決の方向性** - 科学的根拠とともに価値ある道筋を提示
4. **【Narrow down】今日からできること** - 行動ハードルを下げた具体策3項目
5. **【Action】行動喚起** - 要点再掲と前向きな一言で締め

> **注意**: 見出しに（Problem）（Agitation）等のラベルは記載しない

### 各セクションの要件

#### Problem（はじめに）
- 読者の悩みの代弁、安心の提供
- 「僕」で語りかける
- 匿名の短い相談例を1つ（改善結果や施術後の変化は書かない）
- 最小2段落、箇条書き禁止

#### Agitation（なぜ起こるのか）
- 専門用語→直後に平易説明
- 比喩を1つ以上
- 放置リスクは脅かさず淡々と
- 最小2段落、箇条書き禁止

#### Solution（解決の方向性）
- **「どの瞬間で痛いか」で切り分けることから始める**（例：座っている間か、離殿の瞬間か、立ち切った後か）。負担の集まる場所を読者が特定できるようにする
- `症状と困る場面を整理する → 必要に応じて医療機関へ相談する → 安全な対応を検討する` のように、情報整理と役割分担を具体化
- 整体による機能改善や施術効果の確認と読める `調整→変化を確かめる` は使わない
- **受診を優先すべき危険サインの段落を必ず入れる**（安静時・夜間痛、しびれ・力の入りにくさ、発熱・体重減少、外傷後、悪化傾向 → 医療機関での確認を優先）。脅かさず淡々と
- 痛みゼロ原則の明記
- 段階的進行の説明
- 最小2段落、箇条書き禁止

#### Narrow down（今日からできること）
- 3項目を番号付きで
- 研究または公的ガイドラインで裏づけられた場合だけ回数・時間を明記する。直接根拠がなければ精密な数値を作らず、`痛みのない短時間`、`必要な場面で一度`など安全条件・状況基準で示す
- 痛みが出たら中止を記載
- 安全で再現性が高い内容

#### Action（まとめと次の一歩）
- 要点をやさしく再掲
- 「できることから少しずつ」など前向きなメッセージ
- 必要なら相談/予約への導線を自然に提示
- 最小1段落、箇条書き禁止

## 3. 記事テンプレート

### 3.1 シリーズ記事（PASONA＋ナラティブ）

```markdown
## はじめに
読者の悩みを代弁し、匿名の短い相談例を1つ入れる。改善結果や施術後の変化は書かない。僕一人称、です・ます調。

## なぜ起こるのか
専門語→直後に平易説明。比喩を使い、放置リスクは脅かさず淡々と。

## 解決の方向性
症状と困る場面の整理、医療機関との役割分担、安全な対応を文章で具体化。痛みを我慢しない原則と段階進行。

## 今日からできること
1. 〜（根拠がある場合だけ回数/時間。なければ状況基準）
2. 〜（痛みが出たら中止）
3. 〜（安全で再現性が高い）

## まとめと次の一歩
要点をやさしく再掲し、前向きな一言で締める。必要なら相談/予約への導線を自然に提示。
```

### 3.2 単発記事テンプレート

#### 研究レビュー
```markdown
## 背景
## 研究の要点（対象/手法/主要結果）
## 何が言えるか（示唆）
## 限界と注意点（一般化の範囲）
## 実践への翻訳（読者が取れる一歩）
```

#### How To / セルフケア
```markdown
## 注意事項（安全・禁忌）
## 前提（対象・目的）
## 手順（番号付きで具体的に）
## 頻度・回数・所要時間の目安
## よくある失敗と対策
```

#### 症例ストーリー（匿名事例）
```markdown
## 来院背景と主訴
## 評価（所見と仮説）
## 介入（意図と実施）
## 結果（変化と解釈）
## 学び（一般化できるポイント）
```

## 4. 作業フロー

### 4.1 シリーズ記事の場合

1. **参照ファイルの読み込み（必須）**
   - 本ガイド（文体・トーン）
   - シリーズ構成案ファイル（構成・内容の順序）

2. **対象回の確定**
   - 構成案の該当回を読み、固定タイトル・論点・引用資料を把握
   - 前後の記事内容とのつながりを意識

3. **下書き作成（テンプレ準拠）**
   - PASONAの流れを守り、短段落・見出し・箇条書きで簡潔に
   - 専門用語→直後に平易化（必須）

4. **根拠の明確化**
   - 「出典/参考」行で論文・レポート名を明記

5. **文体チェック（必須）**
   - 一人称「僕」、です・ます調、語りかけの自然さ
   - 段落の長さ、見出し階層、太字の要点強調

6. **保存**
   - ファイル名: `NN_固定タイトル.md`（NNは2桁連番）
   - 形式: Markdown（UTF-8, LF）

7. **進捗更新（必須）**
   - シリーズ管理表のチェックリストを更新

### 4.2 単発記事の場合

1. **テーマ確認**: 目的/読者像/前提条件を明確に
2. **テンプレ選択**: 研究レビュー/HowTo/症例から選択
3. **下書き作成**: PASONAの流れで約3000文字
4. **文体チェック**: 本ガイドに照らし合わせ確認
5. **保存**: 適切なカテゴリ配下に `タイトル.md` で保存

## 6. 安全・コンプライアンス

### 必須事項
- **ディスクレーマー**: 本文末に以下を記載
  > 本記事は一般情報であり、個別の診断・治療を提供するものではありません。痛みや違和感が出たら中止してください。症状が続く、強くなる、または日常生活に支障がある場合は、期間にかかわらず医療機関にご相談ください。

- **痛みゼロ原則**: 施術・セルフケアで痛みを押し付けない
- **禁忌事項の記載**: 該当する場合は必ず注意喚起

### 禁止事項
- 誇大表現（「完治」「100%」「即効性」等）
- 断定的な効果保証
- 他者誹謗
- 直接根拠のない精密な回数・時間・セット数（「約」「目安」を付けても不可）

## 7. シリーズ構成案テンプレート

新しいシリーズを企画する際は、以下のテンプレートを使用してLLMにシリーズ構成案を生成させます。

### 入力パラメータ
- `SERIES_NAME`: シリーズ名（例: むち打ち症シリーズ）
- `ARTICLE_COUNT`: 記事本数（例: 5 / 8 / 10）
- `AUDIENCE`: 読者像（年齢層/関心/悩み）
- `GOAL`: 読了後に実現したい変化
- `SCOPE_BOUNDARY`: 扱う範囲と除外範囲
- `KEY_TOPICS`: 必ず含めたい主要トピック
- `EVIDENCE`: 参考にしたい資料の種類や既存ファイル

### 生成プロンプト例

```
以下の入力パラメータで、PBLのスタイルガイドに準拠したシリーズ構成案を作ってください。

- SERIES_NAME: {{SERIES_NAME}}
- ARTICLE_COUNT: {{ARTICLE_COUNT}}
- AUDIENCE: {{AUDIENCE}}
- GOAL: {{GOAL}}
- SCOPE_BOUNDARY: {{SCOPE_BOUNDARY}}
- KEY_TOPICS: {{KEY_TOPICS}}
- TONE: 僕・ですます調・語りかけ
- EVIDENCE: {{EVIDENCE}}

要件:
- PASONAに沿い、各回に『今日からできること』を1〜3項目入れる。
- 専門用語には直後に平易説明を付ける。
- タイトルはそのままファイル名にできる形にする。
- スマホで読みやすい短文・短段落を想定する。
```

### 出力フォーマット

```
【シリーズ概要】
- シリーズ名: {{SERIES_NAME}}
- 対象読者: {{AUDIENCE}}
- ゴール: {{GOAL}}
- 本数: {{ARTICLE_COUNT}}
- 扱う範囲/除外範囲: {{SCOPE_BOUNDARY}}
- 主要トピック: {{KEY_TOPICS}}

【全体設計（ロードマップ）】
- 物語構造（導入→理解深化→応用/実践→総括）
- 各回の役割（認知/理解/行動/信頼形成 など）
- 期待行動（問い合わせ/継続読了/セルフケア着手 等）

【各回アウトライン】
第N回：＜固定タイトル案＞
- 目的（読者の変化）:
- 要点（3〜5項目・PASONA配置を意識）:
- 重要用語（平易説明付き）:
- 参考・出典（あればファイル名/文献名）:
- メモ（注意点/禁忌/次回への接続）:

…（記事数ぶん繰り返し）
```

## 9. よくある落とし穴

| 問題 | 対策 |
|-----|-----|
| 専門用語の説明忘れ・後回し | 用語直後に一文で説明 |
| 段落が長文化 | 2〜4文で改行、視線誘導を意識 |
| 構成案の引用資料が本文に反映されない | 根拠の明確化ステップを徹底 |
| タイトルの微修正 | 固定タイトルは変更不可 |
| 箇条書きの多用 | ナラティブ比率0.7以上を維持 |

## 10. 用語・表記の運用

- **ファイル形式**: Markdown（UTF-8, LF）
- **ファイル命名**:
  - シリーズ: `NN_固定タイトル.md`（NNは2桁連番）
  - 単発: `タイトル.md`

## 11. HPブログ記事の固定要素（WordPress投稿用）

HPブログ記事をWordPressに投稿する際は、以下の固定要素を必ず含める。

### 11.1 記事冒頭と記事末尾の固定要素

#### 記事末尾：JSON-LD構造化データ（SEO/LLMO対策）
**記事の末尾**（フッターの後）に、以下の構造化データを挿入する。詳細な生成方法は「SEO技術ガイド.md」のPart 2を参照。

> **注意**: JSON-LDは記事冒頭ではなく、末尾に配置することで本文の可読性を優先する。

`Article` ノードは必須。`FAQPage` は実際のQ&Aがある場合、`HowTo` は番号付き手順がある場合だけ含める。以下は利用可能なノードをまとめた例であり、FAQや手順がない記事へ機械的に追加しない。

```html
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@graph": [
    {"@type": "Article", ...},
    {"@type": "FAQPage", ...},
    {"@type": "HowTo", ...}
  ]
}
</script>
```

#### 記事冒頭1. TL;DR（要約）
AIが認識しやすい要約を冒頭に配置。

```html
<p class="tldr">本記事のポイントを80〜120字で簡潔に。数字や具体的根拠を1つ以上含める。</p>
```

**TL;DR作成ルール：**
- 全角80〜120字、1文で完結
- 数字または具体的根拠を1つ以上含める
- 読者のベネフィットを明確化
- 「【要約】」などのラベルは記載しない（CSSクラスで識別）

### 11.2 本文末の固定要素

#### 1. 免責事項
本文と参考文献（引用がある場合）の後、LINE案内の前に必ず記載。

```html
<div class="disclaimer">
<strong>※免責事項</strong><br />
本記事の内容は一般的な情報提供を目的としており、個別の診断や治療を意図したものではありません。<br />
痛みや不調がある場合、運動中に痛みが出た場合は中止し、必要に応じて医療機関にご相談ください。<br />
症状が続く、強くなる、または日常生活に支障がある場合は、期間にかかわらず医療機関にご相談ください。
</div>
```

#### 2. LINE案内とCTAボタン
免責事項の後、フッターの前に配置。読者の行動を促すCTAボタンを含める。

```html
<div>&nbsp;</div>

<div>
<p>公式LINEへのメッセージ送信は24時間可能です。返信は営業時間内です。<br />
ご予約や当院の一般的なご案内についてお問い合わせいただけます。</p>
</div>

<p>&nbsp;</p>

<div class="q_button_wrap"><a class="q_custom_button q_custom_button3" href="https://lin.ee/cZKMhZ6" target="_blank" rel="noopener">公式LINE</a></div>

<p>&nbsp;</p>
```

#### 3. 参考文献
研究エビデンスを引用した記事では**必須**。本文で触れた研究はすべて、実在・有効なPubMedリンク付きで記載し、同じPMIDをJSON-LDの `citation` 配列にも入れる。PMID・年・人数・結果の捏造は禁止（確認できない研究は引用しない）。形式は以下。

```html
<h2 id="references">参考文献</h2>
<ul>
  <li>論文タイトル（著者名）<br />
      <a href="https://pubmed.ncbi.nlm.nih.gov/xxxxx/">https://pubmed.ncbi.nlm.nih.gov/xxxxx/</a></li>
  ...
</ul>
```

## 12. 強調表現のルール（WordPress投稿用）

本文内で重要な箇所を強調する際のルール。過度な強調は避け、読者の視線を適切に誘導する。

### 赤字（`color: #ff0000`）
読者に気づいてほしい重要な情報に使用：
- **問題の核心となる事実**（例：「腰痛は10年以上続いていて」）
- **警告的な内容**（例：「若くても歩幅が狭い方は、将来的に腰痛になるリスクが高くなります」）
- **研究結果・エビデンス**（例：「歩幅が年齢相応より10%長い人は、発症リスクが有意に低い」）
- **結論メッセージ**（例：「この小さな意識が、大きな健康につながります」）

```html
<span style="color: #ff0000;">テキスト</span>
```

### 太字のみ（`<strong>`）
具体的な情報や専門用語に使用：
- **具体的な数値**（例：「身長の約45%が理想」「約72cm」）
- **専門用語のハイライト**（例：「代償動作（かばう動き）」）
- **実践ポイント・キーワード**（例：「靴一足分」）
- **記事の問い**（例：「なぜ歩幅が狭いと腰痛になるのか」）

```html
<strong>テキスト</strong>
```

### 太字＋赤字
記事の核心となるキーワードに使用（控えめに）：
- **記事全体を象徴するキーワード**（例：「歩幅がかなり狭い」）

```html
<span style="color: #ff0000;"><strong>テキスト</strong></span>
```

### 使用の目安
| 強調タイプ | 使用頻度の目安 |
|-----------|---------------|
| 赤字 | 1セクションにつき1〜2箇所 |
| 太字のみ | 要点のみ（多用しない） |
| 太字＋赤字 | 記事全体で1〜2箇所 |

### 公開記事の装飾基準

今後のWordPress記事は、公開記事ID `1773` の視線誘導を基準にする。

- 導入の読者の問い・相談文：太字
- 具体的な相談場面：赤字＋太字を1箇所
- 記事理解の核となる重要概念：赤字のみを1〜2箇所
- まとめの中心メッセージ：赤字＋太字を1箇所
- 赤字は `<span style="color: #ff0000;">` を使用する
- 赤字＋太字は `<span style="color: #ff0000;"><strong>…</strong></span>` の順にする
- 件数を機械的に合わせず、記事内で同じ役割を担う語句を選ぶ
- TL;DR、執筆者情報、目次、参考文献、免責事項、CTA、フッター、JSON-LDには記事固有の装飾を追加しない

## 13. 本文のHTML記述パターン（WordPress投稿用）

WordPress投稿時の本文記述ルール。

### 段落の書き方
- 各段落は`<p>`タグで囲む
- 段落内の改行は`<br />`タグで制御
- 2〜4文で1段落、モバイル読みやすさを優先
- 1行は35〜75文字程度、長くても80文字前後を目安に、句点など意味の切れ目で改行する
- 本文の余白調整を目的とした空段落は追加しない（執筆者情報など既定の固定要素は除く）
- リンクや強調タグの途中では改行しない

```html
<p>1文目です。<br />
2文目です。<br />
3文目です。</p>

<p>次の段落です。</p>
```

### 「はじめに」セクションの構成
1. **相談例（患者さんの悩み）から始める** - 自己紹介は冒頭の固定要素で済んでいるため、本文では重複しない。改善結果や施術後の変化は書かない
2. **読者の悩みを代弁する**
3. **記事の問いを太字で提示** - 「今回は、**なぜ〜**、そして**どう改善すればいいのか**、お話ししていきます」

```html
<h2 id="はじめに">はじめに</h2>

<p><strong>「患者さんの言葉をそのまま引用」</strong></p>

<p>日々の相談の中で、同じような不安を聞くことがあります。</p>

<p>お話を聞いてみると、<span style="color: #ff0000;">問題の核心</span>が見えてくることがあります。<br />
こうした悩みでは、まず〇〇を整理することが大切です。</p>

<p>今回は、<strong>なぜ〜なのか</strong>、そして<strong>どう向き合えばいいのか</strong>、僕が日々受ける相談をもとにお話ししていきます。</p>
```

### 見出しの書き方
- `<h2 id="見出し名">見出し名</h2>` 形式を使用
- idは日本語のままでOK（WordPressで動作する）
- 目次のアンカーリンクと一致させる

```html
<h2 id="なぜ起こるのか">なぜ起こるのか</h2>
```

### 記事全体の構造（推奨順序）
1. TL;DR（要約）
2. 執筆者情報（固定）
3. 目次
4. 本文（はじめに〜まとめと次の一歩）
5. 参考文献（研究を引用した場合）
6. 免責事項
7. LINE案内＋CTAボタン
8. フッター（中央画像→院情報）
9. JSON-LD構造化データ

## 14. WordPress投稿・予約投稿

詳細は `WordPress投稿・予約投稿運用.md` を正本として参照する。

- `post_to_wp.py` は固定要素の事前検査とWordPress下書き作成に使う。
- 予約は `format_wp_drafts.py` の `plan → approve → schedule` だけを使う。
- 予約済み記事の固定要素修正は `fixed-elements --status future` をdry-runしてから適用する。
- `post_to_wp.py --publish` に未来日を渡す直接予約は使用しない。
